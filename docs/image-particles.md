# 原画分层 → 网格绑定 → 动作 → 粒子（v3）

## 本轮范围与验收

优先完成**眨眼、轻声说话**，并接入文字短语停顿、停止收口和小幅抬眉。主界面不变。

校对页：**`/preview/character`**。提供补底图、原色联动、粒子联动、五官放大、键盘可用的进度滑块，以及原始静止图／透明部件图集链接。原色和粒子使用同一组顶点与动作，不是两套互不相干的演示。

建议按顺序验收：

1. 补底是否残留眼线、嘴线，是否损伤发际线或出现肤色块。
2. 对照原图检查静止部件的笔触、配色、阴影和边缘。
3. 放大检查开／闭眼及说话 25%、50%、75% 几何中间帧，尤其眼角、睫毛、上下唇连接处。
4. 再切换粒子模式，检查粒度、颜色、位置连续性，并在主界面实际对话。

**测试通过仅代表技术不变量通过，不能据此宣布画风或自然度已获用户认可。** 当前素材是合成后的 PNG，不是 PSD 分层；不可见的底色只能估计，细小交界仍可能需要人工微调。遇到问题先修蒙版、控制点或动作，不能用加粗、提亮、扩大挖洞掩盖。

## 与旧方案的区别

已删除矩形区域目标像素重分配、跨帧颜色混合、常量唇色、程序补画下眼线和三次曲线 SDF 遮挡。矩形现在仅是离线分析／打包范围，不是移动的皮肤贴片。

- 身体、衣服、尾巴、头发与面部补底只采样一次。
- 运动粒子永久属于同一原画部件，保存三角形与重心坐标；RGBA 提取后固定。
- 每帧只混合局部网格顶点，粒子由 `p = w0*v0 + w1*v1 + w2*v2` 得到位置。
- 原色部件预览、遮挡蒙版与粒子全部由相同顶点驱动。
- 主界面绘制的是 `POINTS`，不显示原图、轮播全图纹理或用 `<img>` 冒充粒子。

## 1. 原画部件与固定补底

输入为七张 **1240×1269 RGBA PNG**。原图本来有透明通道，不做全局去白底，白色服饰保留。

`src/images/character.json` 版本 3 保存眼部分析范围、睫毛／闭眼形状引导多边形、眼褶范围、发际线保护、嘴部范围和眉毛像素定位引导。颜色条件只是定位原像素，不生成器官颜色。

`native_layers.py`：

- 从原图定位实际开口、眼球、睫毛、眼褶、上下唇、口腔和眉毛；透明部件只包含原画笔触，不带一整块背景。
- 皮肤／头发分别延展，固定原图边界；眉毛跨越发际线的位置从同一图像的完整横截面克隆修补。**不从未对齐的其他表情图搬运整片皮肤。**
- 抗锯齿边缘使用 `C = alpha*F + (1-alpha)*B` 去除肤色／头发污染，依据附近原画颜料估计 alpha；没有预设的嘴唇或眼线 RGB。强笔触保留原色。
- 鼻尖、嘴线、领口不能合并成同一个红色组件。闭口使用窄范围，开口取连通主体；避免把皮肤或领口绑定成唇部。
- 发际线相交处保留静态遮挡／锚定像素，避免睫毛动画带走头发。

目前是 **11 个可见原画部件 + 3 个开口蒙版**。眼白／虹膜分别有材质标记，但本轮共用固定眼球网格，不额外叠加鼠标视线漂移。嘴内含原画的口腔渐变，不是独立的舌头骨骼。

## 2. 结构网格与固定绑定

`mesh_binding.py` 为原画局部建立三角网格，保留轮廓尖点，避免跨过睫毛尖端。

- **眼睑笼**：上方、上睑、下睑、下方四行控制。开口内随上下睑收拢，主要笔触保留厚度；眼角翼部另混合原画轮廓控制，避免被拉成长须。眼球自身不压扁。
- **眼褶**：保持原笔触厚度、相对间距，联动位移；不把几个细线的包围框拉伸成一块红色区域。
- **嘴部**：上下唇与口腔使用相同口型轮廓。闭口时腔体面积归零；上唇上移、下唇下移，嘴角随轮廓协调。
- **眉毛**：原画笔触绑定，保留线宽；情绪形状来自忧伤图，小幅抬眉只移动网格顶点。

每颗运动粒子保存全局三角形编号及两个量化重心权重，第三个为 `1-w0-w1`。源姿态必须重建其原坐标，不允许最近目标像素匹配。目标与中间帧必须不翻折；开口闭合时允许零面积。

皮肤点不会成为虹膜、睫毛或嘴内点。不同原画材质的身份与提取的 RGBA 都固定。

## 3. 动作库与文字调度

`actions.ts` 中的具名关键点动作可组合：

- 约 250ms 的眨眼，有明确完全闭合段；与说话独立，间隔有变化。
- 轻声以 `rest/soft` 为主，少量浅圆嘴／强调；不全幅轮换大张嘴。
- 短语与标点触发停顿；短语内部不因每个字重启动作，极短语气词可并入后一句。
- 停止后平滑收口，完成后回到静态情绪；思考或好奇时可小幅抬眉。
- 普通短回复按约 48ms／字显示，为动作留下时间；超长回复仍使用快速分块。
- 隐藏页面暂停，减少动态效果时不运行动作循环。

**这只是文字节奏，不是音频音素对口型。** 尚未加入视线追随、独立舌面动作或真实语音同步。

## 4. 粒子与原画遮挡

主界面当前约 **5.9 万点**，其中约 **5.7 万固定点**。RGBA 始终取自同一部件。所有材质共用点核与面积规则，没有嘴唇专用加粗或亮度加成；亚像素点补偿覆盖面积，不强行变成明亮的 1px 点。

口腔用**轻声原画（2）**作为采样基准，而不是将大张嘴（3）的高点数压成细密贴片。口腔蓝噪声点避免张合压缩时出现规则条码。大张嘴、圆嘴图继续提供形状。

WebGL 流程：

1. CPU 每帧只解析约数千个局部顶点，上传当前顶点位置纹理和网格缓冲。
2. 将同一网格变形后的**原画 alpha**绘入遮挡缓冲：R 为主体遮挡，G/B 为左右眼开口，A 为唇口。此通道不画原画 RGB。
3. 一次粒子批绘；顶点着色器读取三角形三个顶点与固定重心权重，片元着色器按实际开口遮挡眼球／嘴内。

这不是整个眼球半透明渐隐：遮挡边界由变形后的真实开口决定。固定皮肤只在实际五官轮廓内受遮挡，周边没有额外扩大挖洞。

原色校对模式才绘制原画 RGB 部件，便于在粒子化之前发现运动错误。图集预乘 alpha 过滤避免边缘污染。主屏只下载编译数据，不加载七张原图；校对页另加载补底 PNG，原始参考仅通过链接按需打开。

Canvas 降级使用同一网格、绑定和原画蒙版；固定点场缓存，动态局部约 15fps。两种后端抗锯齿不同，不保证逐像素相同，但没有另一套公式脸。

## 资源、格式与再生成

```bash
bun run assets:character
bun run assets:character --check
bun run assets:character --preview-dir /tmp/character-preview
```

只在离线生成时需要 Python 3 + Pillow（`scripts/requirements.txt` 固定版本）。`--preview-dir` 导出补底、透明图集与各部件；过渡帧在校对页和浏览器测试截图中检查。

- `native_layers.py`：分层、补底、边缘提取。
- `mesh_binding.py`：网格、源绑定、图集布局。
- `build-character.py`：确定性采样、编译、原图／配置／生成器／校对 PNG 哈希。
- `rig.ts`：共享当前顶点、粒子绑定属性、位置纹理编码。
- `actions.ts` / `animation.ts`：动作与生命周期。

二进制魔数 **`LATMSH03`**，16 字节头：8 字节魔数、描述 JSON 长度、数据长度（uint32 little-endian）。JSON 与各数据段四字节对齐，描述尺寸、计数、部件、源帧、图集布局和数据段类型／偏移。

数据段：源点坐标 uint16、固定 RGBA uint8、四字节粒子元数据、三角形／重心绑定 uint16、部件 ID uint8、七组网格顶点 float32、源 UV float32、三角形索引 uint16、单套原画 RGBA 图集 uint8。**没有七组粒子颜色，也没有七张全图纹理。** 当前顶点位置用 RGBA8 编码，不要求浮点纹理扩展。

解码校验范围、数据段重叠、有限顶点、部件归属和绑定；旧 `LATIMG01/02` 明确拒绝。`--check` 同时比较二进制、清单与两张校对 PNG。

## 自动验证边界

验证源坐标重建、固定材质／RGBA、主体不变、开口归零、嘴部不吸入鼻尖／领口、网格中间帧不翻折、口腔粒度、短语停顿与停止收口。浏览器通过校对 API 同步驱动生产渲染器、读取实际 GPU 像素，比较静态保护区；另测主屏真实像素运动、不请求表情 PNG、降级、重试、移动端、键盘和 axe。

这些约束能防回归，但不衡量原画风格和动作自然度。最终仍以逐帧视觉检查及用户验收为准。
